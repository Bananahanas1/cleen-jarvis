# FUTURE_IDEAS.md — Framtida idéer för Jarvis

Detta är idéer som Jarvis själv föreslog, men de ska INTE byggas direkt.

De ska bara användas som framtida inspiration när basen är stabil.

## Viktig regel

Bygg inte allt på en gång.

Jarvis ska fortsätta byggas steg för steg:

1. Stabil lokal bas
2. Lokala tools
3. Offline-skydd
4. Enkelt agentläge
5. Först därefter större integrationer

## Framtida tools och tekniker

### Lokala utvecklingsverktyg

Kan läggas till senare:

- Git
- Docker
- VS Code
- Python
- .NET
- PowerShell
- Ollama

Dessa ska läggas till försiktigt, ett verktyg i taget.

### Kod- och data-bibliotek

Kan vara användbart senare:

- NumPy
- Pandas
- Matplotlib
- Scikit-learn
- FastAPI
- Flask

TensorFlow och PyTorch ska vänta, eftersom de är tunga.

### Projektverktyg

Kan läggas till långt senare:

- GitHub
- GitLab
- Trello
- Asana
- Slack
- Microsoft Teams

Dessa kräver ofta internet och konton, så de ska vara opt-in.

### Databaser

Möjliga framtida steg:

- SQLite först
- PostgreSQL senare
- Redis senare
- MongoDB senare

Jarvis-clean ska börja med enkla lokala filer och markdown-minne.

### Cloud och DevOps

Ska INTE byggas tidigt:

- Azure
- AWS
- Google Cloud
- Kubernetes
- Terraform
- CI/CD
- Docker Swarm

Detta är för stort just nu och kan göra projektet rörigt.

### Dokumentation

Bra framtida område:

- Markdown
- MkDocs
- Docusaurus
- GitHub Pages

Markdown används redan nu och ska fortsätta vara huvudformatet.

## Rekommenderad prioritet

### Nära framtid

- bättre hjälpmeny

### Mycket senare

## Slutsats

Idéerna är bra, men de ska inte byggas nu.

Jarvis ska först bli stabil, lokal, snabb och säker.
